# 버그 수정 후 재실험 — 1/3경기 완료, EXAONE 일일 한도로 중단

## 상태와 결론

**3경기를 요청했지만 1경기만 완료했다.** 완료 경기에서는 시민 진영이
2라운드 낮 투표로 승리했다. 2경기는 EXAONE 일일 호출 한도로 중단됐고,
3경기는 시작하지 않았다. 미완료 경기는 승률에 포함하지 않는다.

수정 전에는 세 경기 모두 마피아 승리였고, 수정 후 완료된 같은 rotation 0에서는
시민 승리가 나왔다. 경찰의 실제 조사 결과 공개와 의사의 보호가 승리 과정에
사용된 것은 확인할 수 있다. 그러나 **1경기 결과로 시민 승률 개선, 게임 균형,
모델 간 우열을 확정할 수는 없다.** 여러 수정이 함께 적용됐고 LLM 응답도 비결정적이다.

## 실행 조건

기존 [`config.compare.yaml`](../config.compare.yaml)을 그대로 사용했다.
이전 실험 summary와 설정, seed, runner, 최대 라운드가 같음을 검증했고,
완료 경기의 이름·좌석·역할·모델 배정도 이전 rotation 0과 동일했다.

- 모델: `k-exaone_v2.5`, `nvidia/nemotron-3-ultra-550b-a55b:free`,
  `nvidia/nemotron-3.5-super-vl:free`; 모델당 2명
- 6인: 마피아 1, 경찰 1, 의사 1, 일반 시민 3
- seed 42, `graph`, 최대 5라운드, 하루 공개 발언 최대 1회
- API 설정은 이전과 동일: 출력 최대 4,096토큰, timeout 120초, 최대 4회 시도
- EXAONE reasoning `low`, OpenRouter는 모델 기본값
- 기존에 선정한 무료 모델 ID를 고정했다. 실행 전 OpenRouter 카탈로그에서
  두 모델의 입력/출력 가격이 모두 0임을 재확인했다. 주간 순위를 새로 선정하지 않았다.
- 재실험 직전 자동 테스트 **143개 통과**, `git diff --check` 통과
- 코드: `c334dc9` 이후 로컬 버그 수정본. 이번 실행 중 엔진이나 프롬프트를 바꾸지 않았다.

```bash
EXAONE_API_KEY_COMMAND='security find-generic-password -s pi-exaone-api-key -w' \
uv run python -u main.py \
  --config config.compare.yaml --tournament 3 --seed 42 --max-rounds 5
```

2026-11-10 약 **15:32:56–16:03:17 KST**에 실행했으며, 전체 경과 시간은
**30분 20.9초**였다. 실행기 timeout이 아니라 API 한도로 끝났다.
EXAONE 키는 기존 Keychain 명령으로 읽었으며 비밀값을 결과물에 저장하지 않았다.

## 중단 원인

2경기 3라운드 낮에 EXAONE이 다음 오류를 반환했다.

```text
HTTP 429: day limit(100), called 100 times today
code: rate_limit_exceeded
```

같은 모델에 초기 요청과 재시도 3회, 총 4회 시도한 뒤 중단했다.
이 100회는 계정/API 키에 적용된 당일 누적 한도이며, 이번 재실험만으로
100회를 사용했다는 뜻은 아니다. 리셋 시각은 확인하지 못했다.
다른 모델·키로 우회하거나 응답을 만들어내지 않았고 추가 API 호출도 중단했다.

| 경기 | rotation | 마피아 모델 | 상태 | 종료/중단 시점 |
|---|---:|---|---|---|
| 1 | 0 | Nemotron 3.5 Super VL | 시민 승리 | 2라운드 낮 투표 |
| 2 | 1 | K-EXAONE 2.5 | 미완료, 집계 제외 | 3라운드 낮, HTTP 429 |
| 3 | 2 | Nemotron 3 Ultra | 미시작 | — |

토너먼트 JSON의 상태는 `failed`, 완료 수는 `1`이다. `balanced: true`는
균형 순환을 **요청했다**는 설정이지, 미완료된 표본의 역할 균형이 달성됐다는 뜻이 아니다.

## 완료 경기에서 확인한 수정 동작

1. 첫날 밤 경찰 **Emma / EXAONE**이 Alex를 조사해 비마피아 결과를 받았다.
   마피아는 Alex를 공격했고, 의사는 자기 자신을 보호해 Alex가 사망했다.
2. 첫날 투표는 Liam 2표, Emma 2표, Noah 1표로 동률 무처형이었다.
3. 둘째 밤 Emma가 **Liam을 조사해 `is_mafia: true`** 결과를 본인용으로 받았다.
4. 의사 **Noah / Nemotron 3 Ultra**가 **Emma를 보호**했다.
   마피아의 공격 대상도 Emma여서 사망자가 발생하지 않았다.
5. Emma가 조사 결과를 공개 발언으로 알렸다. 다른 사람에게 시스템 결과를
   자동 공개한 것이 아니라, 경찰이 자신의 공개 발언에서 밝힌 것이다.
6. 투표에서 Emma·Noah·Olivia·Ava가 Liam을 선택했고, Liam만 Emma를 선택했다.
   **4 대 1로 유일한 마피아 Liam이 제거돼 시민 진영이 승리했다.**

따라서 조사 → 본인에게 결과 전달 → 공개 발언 → 투표, 그리고 의사 선택 →
공격 방어 경로가 실제 API 경기에서 작동한 것을 확인했다. 다만 이 한 경기로
각 수정의 독립적인 승률 효과를 계산할 수는 없다.

## 부분 출전 통계 — 모델 순위로 사용하면 안 됨

완료한 1경기만의 기록이다. 탈락한 플레이어도 소속 진영이 이기면 승리로 센다.
모델별 역할 구성이 다르므로 아래 비율은 서로 공정한 성능 비교가 아니다.

| 모델 | 배정 역할 | 승/출전 | 부분 출전 승률 |
|---|---|---:|---:|
| K-EXAONE 2.5 | 경찰·일반 시민 | 2/2 | 100% |
| Nemotron 3 Ultra | 의사·일반 시민 | 2/2 | 100% |
| Nemotron 3.5 Super VL | 마피아·일반 시민 | 1/2 | 50% |

진영별로는 완료 경기 기준 시민 **1승/1경기**, 마피아 **0승/1경기**다.
기존의 균형 잡힌 3경기 모델별 16.7%와 위 부분 통계를 직접 비교해서는 안 된다.
